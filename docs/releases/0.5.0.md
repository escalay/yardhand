## Search now returns only what clearly matches

- **A search that matches nothing returns nothing.** `search_tools` and `GET /api/tools?q=` return only tools that clearly match the question. Before, they returned the nearest tools every time; now a question that matches nothing answers `count: 0`.
- **What it costs, measured.** Replayed on one instance's log of agent searches (57 where the agent went on to call a tool; 53 of those tools can still be returned): the tool the agent then called was still returned in 51 of 53 (before: 53 of 53) and was first in 26 (before: 26). Four gibberish queries returned 20 tools each before and none after. An off-topic query in a 24-tool pack went from about 9 results to under 1.
- **The app still filters as you type.** The owner's search boxes in the app keep every keyword hit, so half a word or a connection's id still lists its tools. Keys, scripts and agents get the stricter search.
- **Small gateways search as before.** A gateway with fewer than 50 tools, or without search by meaning, is unchanged.
- **A pack key sees its pack's own counts.** `list_upstreams` and `GET /api/upstreams` count only the tools, playbooks and manuals the pack holds, and `GET /api/links` is empty for a pack key.
- **For scripts.** `GET /api/tools` has a new field, `hint`: null except when a pack key's search matched nothing in the whole pack, where it says what the pack covers. `count`, `limit` and `hiddenForScope` there now count tools as the caller reads them, so a pack tool under two names counts twice.

Nothing to do by hand: no new setting, no data change.

## Every pack has its own address

- **One thing to do by hand, where a proxy or an access rule in front of Yardhand lists paths.** Let `/p/*` through as `/mcp` and `/api` are, or the new addresses stay shut. Nothing else by hand: no new setting, and the packs table gains one column by itself.
- **One address per pack.** A pack is served whole under `/p/<pack>/`: MCP at `/p/<pack>/mcp`, REST under `/p/<pack>/api`, its own guide at `/p/<pack>/llms.txt` and its own docs at `/p/<pack>/docs`. The guide and the docs describe the pack and nothing else of the gateway. The pack's page in the app shows the address, with setup for each app.
- **The old address and the header still work.** `/mcp/p/<pack>` and the `x-gateway-pack` header answer as before, and plain `/mcp` still serves a key's default pack: nothing has to be reconnected. One correction: the header sent to `/mcp` by a key with several packs now gets the pack it names, where it was served the key's default pack. Setup for a key with several packs, and `packs[].mcpUrl` on `GET /api/me`, now hand out `/p/<pack>/mcp`.
- **A pack connection has the gateway's shape, under the pack's name.** It has the search and call tools (`search_tools`, `describe_tool`, `call_tool` and the rest) over the pack only, with the pack's tools listed directly beside them. The server introduces itself by the pack's name and title where it said Yardhand, its instructions and those tools speak of the pack, and its starting prompt is `use_pack` where it was `use_gateway`.
- **Agents already connected to a pack keep their tools.** Every tool of the pack is still listed directly and called as before, and a search that fits nothing now says what the pack covers.
- **Pins make a pack lean for one key.** Pin tools for that key with `PATCH /api/clients/{id}` and `pins`, by the pack's own names: the key then lists only its pins and finds the rest of the pack with `search_tools`. `pins: null` brings the whole pack back. The pins on Tools › Pins never apply inside a pack. A pack key that was given `pins` through the API on an earlier version, where they did nothing, is narrowed to them now: clear them with `pins: null` if that was not meant.
- **Your own key works at a pack's address.** The owner's key there, or with the header, was refused; it is now answered as a write key of that pack, to see the pack as its agents do. Managing the gateway stays at `/api` and `/app`.
- **Pack addresses take keys only for now.** Signing in to a pack from claude.ai or ChatGPT comes later. `/p/<pack>/docs` opens in a browser only for the signed-in owner; anyone else reads the guide and the OpenAPI document (`/p/<pack>/openapi.json`) with their key.
