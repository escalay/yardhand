## A playbook's arguments as their own query parameters

- **`?topic=tides` works.** `GET /api/playbooks/{name}/messages`, and the same under a pack's address (`/p/<pack>/api/playbooks/{name}/messages`), now takes each argument as its own query parameter, named as the playbook names it. `?arguments=<JSON>` works as before, and the two can be mixed.
- **A wrong name says what is allowed.** A query parameter the playbook doesn't take is a 400 that lists its arguments (`Unknown query parameter topik. Allowed here: arguments, topic.`), and an argument given twice, or both ways, is a 400 too. Before, every name but `arguments` was refused this way, the playbook's own arguments included.
- **A missing argument shows a use that works.** Over REST, the 400 for a required argument left out ends with the address to send: `Send each as its own query parameter: GET https://gw.example.com/p/<pack>/api/playbooks/<name>/messages?topic=<topic>`. Over MCP it reads as before.
- **The guides say so.** `/llms.txt` and each pack's guide (`/p/<pack>/llms.txt`) show the form, and a pack's guide gives each playbook's address with its arguments.
- **For scripts.** A script that matched the exact text of the missing-argument 400 must allow the sentence now added at its end.

## Two more checks on a pack's skill

- **A playbook the skill names that the pack lacks is said.** A skill that names a playbook in its Playbooks section (in backticks, or as a list item's leading name), or a connection's playbook (`<upstream>-<prompt>`) anywhere, that the pack does not have gets a warning, `unknown_playbook`, naming it. It is a warning: the skill is still saved.
- **A file's name is not taken for a tool's.** A backticked name such as `tokens.css` or `demo-effect.css` no longer gets the `unknown_name` warning. One named after a connection of the pack (`<upstream>.<tool>`) is still read as that connection's tool.

## Search by meaning tries again by itself

- **A refresh that did not finish is tried again.** When the vectors for search by meaning were refreshed and the provider failed, or the key's spend cap or the refresh's own budget stopped it, nothing tried again until a sync changed tools, so tools approved meanwhile were found by their words only, for days. It now tries again after 1 minute, 5, 30, 2 hours, then every 6 hours, and the vectors made before it stopped are used at once.
- **Settings › AI says when tools have no vector.** The search card says how many tools search finds by their words only, what stopped the last refresh and when it tries again. `GET /api/ai` has it as `vectors` on the `search` job (null for the other jobs, and while search has no key).

Nothing to do by hand: a restart also refreshes them, as before.

## A group named after its connection stays as it is

- **No more "Weathers".** Grouping by rules made a group's title plural from its tools' noun, also when that noun was the connection's own name (`weather` → Weathers) or a word with no plural. It now keeps the connection's word as the connection writes it, and words such as weather, data, metadata or feedback as they are.
- **A group already named so keeps its name.** Only new groupings are named this way: rename one under the connection's Groups. Group keys are unchanged.
