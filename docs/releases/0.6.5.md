## A key is shown once, even to a retry

Yardhand's built-in kit moves from 1.29.0 to 1.33.0. Apps signed in before the update keep working and are not asked
to connect again. What you may notice:

- **A request that made a key, sent again with the same `Idempotency-Key`, no longer gets the key again.** Making a
  client (`POST /api/clients`), sharing a pack (`POST /api/packs/{name}/people`), claiming a new instance and signing
  in to the app answer the key, the share message or the session cookie once. Sent again within a day with the same
  `Idempotency-Key` and body, the request makes nothing and is a 409 `shown_once` whose `detail` names what was made
  and what to do if the first answer was lost (revoke it and make another). The key is never kept, sealed or not.
  The app at `/app` sends no `Idempotency-Key`, so it sees no change; a script that retried to get a lost key back
  revokes that client and makes a new one instead. Every other request is repeated as before.
- **The first start forgets every answer kept for an `Idempotency-Key`.** For the day after the update, a retry of a
  request first sent before it runs again instead of being answered from before.
- **Over MCP, an `Idempotency-Key` on the request to `/mcp` reaches each tool call.** Each call in it is kept under
  that key and the call's own id, so a tool call sent again with the same key and id runs once, and two calls never
  share a key.
- **A forwarded host is taken only when it is a bare host.** An `X-Forwarded-Host` with a path, query, user or
  fragment in it (`localhost/p/other`, `someone@host`) is ignored for the address the request came by, and an
  `X-Forwarded-Proto` other than `http` or `https` likewise. Behind Cloudflare, Traefik, Caddy or nginx nothing
  changes: they forward a bare host. With `PUBLIC_HOST` unset or naming this machine, the sign-in documents, a
  token's issuer and audience and a pack's links follow a forwarded host only when it is bare.
- **An app's sign-in that ends before it gets its first token leaves no agent behind.** When a sign-in is ended
  while Yardhand makes its agent (the same code sent twice at once, say), the agent made for it is removed again
  instead of staying on the Agents page with no way in.
- **Two refreshes sent at once no longer sign an app out.** A refresh token sent again within 30 seconds (two
  refreshes at once, or a retry after a lost answer) gets the same new token the first one got. Sent again later, it
  still ends that whole sign-in and the app connects again, as in 0.6.4.
- **Apps' refresh tokens look different.** Those issued from now on name their sign-in (`rt_<grant>.<n>.…`) and
  leave no used row behind each refresh. Tokens issued before the update keep working and refresh as before.
- **The approval page names an app's own scheme as where it returns** (`app-name:`): only an `http` address on this
  machine (`localhost`, `127.0.0.1`, `[::1]`) is "an app on this computer" now.

Nothing to do by hand: no setting and no data change.
